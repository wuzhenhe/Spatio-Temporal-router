# Anonymous-release checklist

The tracked project files have been prepared without author, affiliation, email, personal URL, local absolute path or credential information. Anonymity can still be broken by Git hosting metadata, which is not stored in this source directory.

Before submission:

- Create a fresh repository under an account or organization that complies with the venue's anonymity policy.
- Upload only the contents of this directory. Do not preserve the parent project's `.git` directory or commit history.
- Use a non-identifying commit author name and email. Inspect them with `git log --format=fuller` before sharing the repository.
- Inspect `git remote -v`, the repository owner, profile, issue/PR activity, Actions logs and package/container namespaces for identifying information.
- Keep the repository description and README free of the paper title when the title itself could identify an existing preprint or project.
- Do not commit model/data caches, experiment outputs, absolute local paths, hostnames, usernames, credentials or private download URLs.
- Open the repository in a logged-out/private browser session and verify that no account, fork, sponsor or organization relationship reveals the authors.
- Follow the submission venue's own policy if it differs from this checklist.

The anonymous review copy intentionally omits author citation and license attribution. Add the final citation, acknowledgements and an appropriate license only after anonymous review, after checking all applicable third-party terms.
